## Methodology

### Error-injection harness (`scripts/error_injection.py`)

Re-uses the 20 hand-authored fixtures from Phase 2 (`tests/fixtures/golden_traces.py`):

- **10 VALID traces** — tautologies, modus ponens, syllogism, transitivity, arithmetic, quantified instantiation, contrapositive, etc.
- **10 INVALID traces** — affirming the consequent, denying the antecedent, unrelated conclusion, existential overreach, conjunction-from-disjunction, sign-reversal, off-by-one equality, double negation, bound mis-reading.

Each trace is fed through `Verifier` with a `FakeLLMClient` pre-seeded with the canonical SMT formalizations. A trace is "caught" iff at least one step verdict is `INVALID`. The verifier classifies every fixture correctly.

### Three end-to-end scenarios (`scripts/run_benchmark.py`)

Drives the full `StateGraph` (research → design → execute → analysis) against the `LabSimulator` (Phase 5) with a deterministic stub result so the analysis step's prompts align. Each scenario exercises a different `LabSimulator` instrument route:

- **`protein_crystallization`** — liquid-handler keyword → `volume_dispensed_ul`.
- **`compound_activity`** — plate-reader keyword → `absorbance`.
- **`materials_optimization`** — imaging keyword → `intensity`.

For each scenario, the graph runs to completion with 4 verifier passes (one per producing agent) all clearing the HITL threshold.

## What this benchmark does NOT prove

- **Real-LLM behaviour.** Every test path uses `FakeLLMClient`. The `ClaudeLLMClient` adapter exists and is wired into the CLI, but live tests are gated on `RUN_LIVE_TESTS=1` and require an API key — neither is set in CI.
- **Real lab hardware.** The `LabSimulator` is deterministic with Gaussian noise; real instrument drift, queueing, and failures are not modelled.
- **Adversarial reasoning errors.** The 10 INVALID fixtures are textbook fallacies; real research traces will be subtler.

## Recommended next steps

1. Add a `RUN_LIVE_TESTS=1` job to CI once an API key is available.
2. Extend the error-injection corpus to ≥ 50 traces, drawn from `ProofWriter` / `LegalBench` style examples.
3. Replace `LabSimulator` noise model with per-instrument empirical distributions when real hardware data is available (Phase 5b).
4. Pull the dashboard (Phase 6) into a CI screenshot test.
